# History of the lab

The steps of the lab, in order. Each step gives what we added, and what a Run taught us when a Run caused the step. Use it as the plan of a video. Add a step at the end of each piece of work.

## 1. The emulator and the Viewer (2026-10-09 to 10-10)

1. A lab build of FireRed (`make lab`): the same game, plus a direct boot to "Continue" and a fixed RNG seed. The emulator (libmgba) runs in Bun; the browser only shows the game (ADR 0001). `11ebe5b9d`
2. The Viewer: the screen, the keyboard, the speeds, the savestates, and an overlay of the cells (collision, water, ledges, warps, people). `11ebe5b9d`

## 6. The Viewer renewal: spec #54 (2026-10-27 to 10-31)

49. The Viewer is renewed (spec #54). Before, the Viewer had grown one panel at a time: plain DOM and about 290 lines of inline CSS, panels in a row with fixed widths, long lists of text, and a Doc that was one long page. Now each part comes from one design system that a Components tab shows (ADR 0004: Preact, Tailwind v4 and Lucide, with no build step). The Lab tab has a top bar on one line, a left column with the screen, its controls, the decision line and the cards of the party, a rail of tool panels (Whole map, Model, Stats, Memory tree, Bag and PC) and a Timeline of the Game events at the bottom. One cursor and one selection move all the panels together. The Run record gets new Game events for the Timeline and the Stats panel, and the Doc is a side list of short pages. A click on the Timeline or on a Model call jumps the screen of a replay to that frame, forward and back, from a savestate that the server keeps. Each part started as a prototype with variants in the real Viewer, on a replay of `model-10`; the user chose one, and the verdict is in its issue. The spec ended in 14 tickets in 5 days (#55 to #68); the jump in a replay (#66) became a part of the Timeline (#65). The spec did not change the model prompt or the model bot version; the Run record keeps the same keys, and its format 1 adds the Game events. The paragraphs below tell each ticket.

    The Viewer gets a design system (issue #55). The Viewer had grown one panel at a time: about 290 lines of CSS inline in the page, and DOM built by hand in each panel. The user chose a direction from a prototype with three of them, "Glass bento" (a dark blue, one periwinkle accent, translucent cards), over "Instrument" (flat and dense, orange) and "Pokédex" (heavy borders and offset shadows), and asked for a second, simpler iteration with only the base components and no glow. The Viewer now uses Preact, Tailwind v4 (compiled by Bun with its plugin, with no build step), Lucide for the icons, and Raleway and JetBrains Mono from Fontsource (ADR 0004). A third tab, Components, shows each component in all its states: type, colors, button, field (text, number with a unit, select, search, error), switch, checkbox, tabs (line and segmented), pill, bar (HP in the colors of the game), number, card and tooltip. Each one has a small motion: a button scales when you press it, a tab indicator slides, a bar leaves a trail when its value falls, a number counts to its new value, a card takes the accent on hover. All motion stops with reduced motion. The navigation bar is the first part of the Viewer that uses them: the name of the lab and the three tabs, with an icon and the sliding indicator. The old panels keep their CSS in a cascade layer below Tailwind, until they move to the components. `AGENTS.md` and the coding standards now tell agents and reviewers to use these components, and to ask the user before they make a new one.
